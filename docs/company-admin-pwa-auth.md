# GOLD FIRST 法人担当者登録管理 — PWAログイン改善（検証用）

## 目的
iOSホーム画面Webアプリ / Androidホーム画面Webアプリから、外部ブラウザでLINE認証を完了しても元のPWAへログイン状態が戻らない問題を解消する。

## 重要な制約
- PWAとChrome/Safari/LINE内ブラウザのcookie・sessionStorage・localStorage共有を前提にしない。
- LINE IDトークン、アクセストークン、管理者セッショントークンをURL・QR・クリップボードに載せない。
- 既存 `gf-company-admin-api-demo` と `company-admin/enroll.html` は本番稼働中。切り替え前に変更しない。
- 本人確認後も全API呼び出しで `gf_company_admin_identities.active` と `role` を検証する。
- 端末紛失時のセッション失効、ログアウト、期限切れ、レート制限を必須とする。

## 方式：二画面ペアリング
1. PWAがバックエンドへログイン要求。ランダムな128bit以上の照合用秘密と、5分有効の短い表示コードを発行する。照合用秘密はPWAだけに保存。
2. ユーザーがLINE内の認証ページを開き、PWA画面の表示コードを入力する。LINE IDトークンをバックエンドで検証し、管理者権限を確認する。
3. PWAは照合用秘密で承認完了を問い合わせ、成功時だけ新規端末セッションを取得する。表示コードだけではセッションを取得できない。
4. セッショントークンは暗号学的乱数から発行し、DBにはSHA-256ハッシュのみを保存。原文はPWAにだけ返す。
5. PWAは以後セッショントークンでAPIを呼び、毎回管理者の active / role を再確認。7日を超えると再認証。
6. ログアウトでセッションを無効化。本人が端末を紛失した場合の管理者一括失効も設ける。

## セキュリティ受入条件
- 未承認LINEアカウントからペアリング不可
- 無効化された管理者の既存セッションを即時拒否
- 表示コード総当たり対策（試行回数、IP/主体ごとのレート制限）
- 二重承認・期限切れ・再利用を拒否
- 外部サイトからのCORSリクエストを拒否
- サーバーログに認証秘密を出力しない
- PWAとChromeの保存領域が完全に分離されていても動作
- iOS / Android 実機で認証、再起動、期限切れ、ログアウトを検証

## 公開手順
1. 既存のDBとAPIを変更せず、独立した検証用エンドポイント・ページを作成
2. 自動テストとLINE実機テスト
3. ユーザーの確認後に法人担当者登録管理だけ切り替え
4. 旧方式を切り戻せる状態で保持
