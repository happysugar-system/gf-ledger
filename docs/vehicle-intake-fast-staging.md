# 車両依頼受付高速化 — 安全な切替設計（実装ブランチ）

対象: `vehicle-request.html` / GAS100 `GF_車両テスト送信_` / GAS140 `GF_車両ブリッジ受付_` / GF145/146 / Supabase

## 現状（確認済み）
- GitHubフォームは5ページ、契約確認チェック、免許証表裏、住民票PDFまたは郵送を扱う。
- GAS100 は期限付き `gf_entry` をサーバーキャッシュで検証し、別GASに同期POSTする。
- GAS140 は GF145 の受付保存後、GF146 のDrive保存が終わってからJSONを返す。
- Supabase `gf-secure-intake-staging-test` は管理者限定・STAGING受付番号限定。
- `gf135-transfer-ticket-test` はテストドライバー D999999 固定。一般利用者向けに転用禁止。

## 目標と完了の定義
1. LINE発行の期限付きトークンをGAS側で検証し、LINEユーザーIDをブラウザに返さない。
2. 受付情報を永続保存し、再送しても同じ受付番号になる（idempotency）。
3. 書類を非公開Supabase Storageへ保存し、種類・サイズ・マジックバイト・SHA256を検証する。
4. 必要書類の保存確認後にのみ受付番号を表示する。郵送選択時はPDFを要求しない。
5. Drive転送は後続ジョブで実施し、失敗は再試行可能な状態に残す。
6. GF115受付反映の二重実行を防ぐ。受付状態とDrive転送状態を分ける。
7. 既存GAS132〜136、LINE Webhook、5ページ構成、契約チェックは変更しない。

## 本番切替前の必須条件
- 一般利用者がSupabaseへアップロードするための**サーバー検証済み一回限りの権限**を実装する。Origin/CORSや公開トークンだけを本人認証に使用しない。
- Supabaseの管理者用テスト関数を公開利用者向けに改造しない。
- 保存済み受付情報と書類を結びつける受付IDをサーバーが発行する。
- `gf135-transfer-ticket-test` の固定DriverIDを本番へ流用しない。
- 失敗時に「受付完了」と表示しない。復旧可能な保存状態を管理する。
- ダミーデータで新規、重複送信、PDF郵送、容量超過、認証切れ、転送失敗、再試行を検証する。

## 段階的な実装
A. 新しい非公開受付API（GASトークン検証と紐づく署名付き短期セッション）を実装。
B. Supabaseの受付テーブル・書類テーブル・private Storageを受付IDで関連付け。
C. GitHubフォームの送信部分のみ変更し、入力画面と契約チェックは維持。
D. 受付完了後のDrive転送ワーカーとGF115反映を冪等化。
E. テスト合格後にのみ本番経路へ切り替える。
