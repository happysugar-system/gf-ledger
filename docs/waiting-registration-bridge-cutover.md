# 名変待ち登録のスタッフAPI・GAS接続

## 現状

提示されたGASは過去の取得記録上、車両・ドライバー管理用。共有ファイルには172系の定義がある。現行のプロジェクト名、対象ブック、doPost/doGet、デプロイ、所有者別トリガーは現行エディターで確認する。過去に記録された別の本番Script IDがあるため、提示先を本番・検証いずれかと断定しない。

## 追加と変更の候補

|対象|変更|
|---|---|
|既存の車両管理GAS|GFA_StaffWaitingBridge.gs を追加し、既存の doPost に専用分岐を追加|
|172_GF138_名変待ち連携.gs|登録関数へ任意の確認DriverID引数を追加。既存の2引数呼び出しを維持|
|gf-line-reception-admin|既存認証・権限・受付照合を通過した waiting_register のみ署名付きでGASへ送信|

既存 doPost が見つかった場合、入口で次の2行を実行し、該当しないイベントは既存分岐へ渡す。doPostそのものを二重定義しない。現行入口と公開範囲を確認した後に統合する。

```javascript
const waitingResponse = GFA_スタッフ受付受信_(e);
if (waitingResponse) return waitingResponse;
```

GASの GFA_スタッフ受付設定を準備 は GFA_STAFF_BRIDGE_ENABLED がないときだけ false を追加する。既存設定を一括置換しない。GASの GFA_STAFF_BRIDGE_SECRET と Edgeの GF_WAITING_GAS_SECRET に、同じ環境専用の高エントロピー共有値をそれぞれの管理画面で設定する。Edgeの GF_WAITING_GAS_URL に照合済みの検証用 /exec を指定する。検証時は GF_WAITING_REGISTER_ENABLED と GFA_STAFF_BRIDGE_ENABLED を明示的に有効にする。設定値・署名・受付キーはログに出力しない。アプリ側の既存認証を使う。署名なし・改変・期限切れではGAS登録に進まない。同じ受付を再送しても既存GFAの重複判定が働く。

## 検証と本番移行

既存の検証2冊と goldfirst-demo を再利用する。R01/R02/R03は証跡として保存。固定IDの既存テストワーカーを新規受付へ向ける前に、スタッフ画面・マイページ・同期ワーカーが同じ検証データを指すことを確認する。新しいダミー受付での成功・拒否・二重登録、割当・取消・再割当、進捗後取消、納車2日付、台帳直接変更からの同期、本人表示、免許証の空欄補完と既存値維持を実地で確認する。

複数車両は受付とVehicleIDで特定する。既存割当済みDriverIDの新規登録を止めるGFAのルールは維持。複数台同時利用を登録できるようにするには、受付別に過去と現行の割当を識別できる記録と承認済み業務条件が必要。

配備前に現行GASソース・稼働版・トリガーと対象行を控える。検証で合格後、承認を受けて既存デプロイを更新する。既存トリガーをそのまま使用する。障害時はまずEdgeとGASの有効化フラグを停止し、既存Webアプリの旧版とEdgeの旧コミットを復元する。影響行はバックアップと照合して個別復旧する。

資産と整理候補は docs/waiting-registration-release-readiness.md を参照する。検証コード、差分、結果、バックアップと復旧記録をGitHubで管理。リソース停止・削除は依存調査・バックアップ・承認の後に行う。
