# GOLD FIRST 車両進捗の検証

11月24日のスタッフ画面プレビューと既存の割当・取消を起点とする。車両台帳を正本にする。割当時は管理区分を「車両準備中」とし、区分/ステータスは現行の割当経路どおり扱う。進捗では管理区分を手入力する。納車可能日と納車確定日は別項目として扱い、両方がある場合は確定日を可能日以降とする。

## 検証用コード

- `integrations/gas/gf-ledger-progress-test.gs` は既存の `GFI_確認_` と同じスクリプトロックを使う。対象は検証行のみ。Sheets APIの一括更新で3セルの値を保存し、入力規則・表示形式・他の列を維持する。既存プロパティの読み書きは発生しない。
- `node --test tests/ledger-progress.test.mjs` で入力、競合、取消ガードを確認する。
- 直接編集の検出は保存直前の照合で行う。スクリプトロックは同じGASの処理間に効く。スプレッドシートの同時手編集をロックする機能はない。
- 取消ガードは単体検証済み。現行取消処理への組み込み前は、納車日のみ入力した状態での取消を実機で行わない。

## 検証環境への接続前に確認する項目

1. 検証ブックで「納車可能日」「納車確定日」の実ヘッダーと日付表示形式を確認する。検証用スタンドアロンGASで既存の `GFI_確認_` と実際に稼働中のワーカーを照合する。このファイルの実行には高度なGoogleサービスのSheets APIが必要。
2. 既存受付と同期の処理を拡張し、保存後の台帳スナップショットからSupabaseのレプリカとマイページ進捗を更新できるようにする。現行Edge Functionは厳密な固定レコードを要求し、追加列と任意の管理区分を受け付けない。進捗保存を公開する前に同期経路を対応させる。
3. 既存の取消処理の同一ロック内にガードを組み込む。取消の対象が「車両準備中」で、納車日が空欄の場合に既存処理へ渡す。台帳直接編集の反映には既存の同期処理への接続が必要。
4. TEST-001を割り当て、スタッフ画面で管理区分と日付を入力し、台帳と検証マイページで照合する。台帳で片方の日付を変更し、再同期後のマイページを確認する。進捗変更後の取消が拒否され、台帳とマイページが維持されることを確認する。
5. 本番用の正式な管理区分の表示文言と取消可否、本番GASの保存関数・既存プロパティ・同期設定・LINEマイページの取得経路を確認する。実機試験後に本番差分と復旧手順を確定し、承認後に反映する。

既存の [割当・取消検証画面](https://happysugar-system.github.io/gf-ledger/vehicle-driver-assignment-integration-test.html) と [マイページ検証画面](https://happysugar-system.github.io/gf-ledger/mypage-assignment-progress-test.html) は個別の確認に使える。新しい進捗保存の公開、既存ワーカーへの接続および本番コードの確定は未完了。
