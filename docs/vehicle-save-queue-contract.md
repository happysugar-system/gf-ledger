# 車両保存キュー 接続仕様（未実装・未公開）

既存受付・ドライバー同期キューとは分離する。正本は車両台帳。
初期対象は隔離テストのGPSのみ。本番VehicleIDへの書き込みは禁止。

## 通信契約
- スタッフAPIは既存の本人確認と gf_staff_access_self による権限確認を毎回実施。
- サーバーが request_id と actor_id を確定。ブラウザの actor_id は信用しない。
- 更新要求には vehicleId, expected, changes を含める。GPSは真偽値のみ。
- キューはブラウザから直接読み書きできない設計とする。
- GASワーカーは専用のサーバー間認証を利用し、認証情報をブラウザへ渡さない。
- ワーカーはリース付きで要求を取得する。完了通知には request_id とリース識別子を必要とする。
- 同じ要求の再送は重複書込しない。書込後の応答喪失は自動再書込せず照合待ちとする。

## 状態
queued → processing → sheet_verified → replica_verified
失敗時: conflict / rejected / reconciliation_required
HTTP 202 は受付のみ。保存完了ではない。
replica_verified は正本とSupabaseの反映を確認した場合のみ設定する。

## 本番接続の条件
1. 現行の車両台帳→Supabase更新経路を特定。
2. スタッフ権限・キューアクセス制限・サーバー間認証を実装して検証。
3. 隔離テストシートでGF126の実動作を確認。
4. 直接シート編集との競合・応答喪失時の再照合を検証。
5. 予定・ステータス・カレンダーは既存専用処理と統合するまで対象外。

この文書は接続仕様のみ。キューのDB作成、API公開、GASトリガー作成は行っていない。
