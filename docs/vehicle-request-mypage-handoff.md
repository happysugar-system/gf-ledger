# 車両依頼フォーム → マイページ初回登録：接続仕様

## 既存実装で確認した事実（2026-11-12）

- `vehicle-request.html` の `demoSubmit()` は、`action=gf_vehicle_submit_test`、`gf_entry`、氏名・連絡先・免許証などを **HTMLフォームPOST** し、`target='_self'` でGASの `/exec` ページに遷移します。
- **受付完了画面は送信元HTMLではなく、POST先のGASレスポンス側が表示する必要があります**。送信元に成功の文言を先に表示すると、受付失敗を成功と誤表示します。
- `gf-mypage-demo/mypage-prod-test.html` はメールOTPログイン、初回登録申請、管理者の確認・DriverID紐付け後の表示に対応するテスト画面です。
- 今回の `vehicle-request-complete-demo.html` は**表示・遷移を確認するだけのデモ**であり、申込を登録・受領する機能はありません。

## 正しい本番接続方法

1. **受付を処理するGASプロジェクト**（`GF_VEHICLE_SUBMIT_URL` が指す側）の `gf_vehicle_submit_test` 受信処理を確認する。今回GitHubに取り込んだ `GF-GAS-TEST` がこの受信側と同一とは限りません。
2. サーバー側で依頼の保存成功・受付番号生成を確認した**後に限り**、成功HTMLに「車両依頼を受け付けました」および登録リンクを表示する。
3. デモで確認した導線：`https://happysugar-system.github.io/gf-mypage-demo/mypage-prod-test.html`
4. リンクのURLには氏名・電話番号・メール・DriverID・受付トークン・免許証情報など**個人情報や認証情報を入れない**。本人確認とレコードの紐付けは認証済みSupabaseユーザーとサーバー側の承認・RLSで行う。
5. 受付失敗・タイムアウト・重複送信では成功画面を表示しない。二重登録防止・受付番号の一意性を確認する。
6. 申込データ→マイページ用テーブル同期、メール本人確認、管理者承認、DriverID紐付けまで、**一連のテスト**を行う。
7. 公式LINEの「マイページ」ボタンは登録完了後も使うため、テスト中はテストLINEでのみ設定。安定後に正式なマイページURLに切り替える。

## サーバー側の成功画面に置く文言の案

> 車両依頼を受け付けました。お申し込みありがとうございます。お申し込み状況や車両情報はドライバーマイページで確認できます。まずはメール認証による初回登録をお願いします。

ボタンの表示名：**「マイページの初回登録へ進む」**

**注意**: 既存マイページの初回登録は、本人情報を入力した後に管理者の確認を待つ設計です。「登録した瞬間に必ず全情報が表示される」と案内しないこと。

## これから必要な作業

- 実際の受付GAS側のソース取得（送信受付・保存処理と成功HTML）
- GAS側成功レスポンスのみへのリンク実装と安全確認
- 受付番号／メール／DriverIDの照合ロジック・権限と同期の確認
- テストLINE→受付→初回登録→承認→マイページ→LINE再訪までの一気通貫テスト
