# 車両進捗の本番移行準備

本番切替の判定は保留。検証GASの原本、台帳保存プログラムの候補、ローカル回帰テストをこのブランチに保存した。現行画面・本番GAS・トリガー・Supabaseの稼働版は切替前に特定する。

## 確認済みの仕様

車両台帳を正本にする。割当時に区分/ステータスを貸出中へ自動変更しない。管理区分は「車両準備中」から始め、既存DriverIDを使う。ユーザー確認済みのマイページ表示は「申込受付」「契約締結」に続く「車両準備中」「車両手配済み」「名義変更前」「名義変更中」「名義変更済み」の7段階。納車可能日と納車確定日は別項目とする。社長との直接の合意記録、複数車両を使うドライバーの表示対象、各段階の更新日時の保管経路は切替前に確認する。

## 検証台帳と本番台帳

|項目|検証|本番|

## 切替前の接続確認

1. 本番台帳から Apps Script を開き、稼働プロジェクトのソースと appsscript.json、適用済みのデプロイ版、トリガーの関数・所有者・頻度を確認する。割当、取消、編集、カレンダー、名義変更、Supabase同期を呼び出し元から追う。トリガーを所有者ごとに確認する。プロパティはキー名を照合し、実値は共有しない。
2. 本番の名変待ち管理にない3列を前提にしない。現行の受付識別子と確定DriverIDの照合経路を確認し、割当済み対象が車両台帳・名変待ち・ドライバーマスターで一致する条件を実装に渡す。既存の割当と取消を変更する前に複製環境で操作する。
3. 既存スタッフ認証、権限、契約完了、確定DriverIDをチェックしたサーバー側から、台帳保存用GASを呼び出す。直接Supabaseに書く進捗経路との二重運用を避ける。GASの保存候補は関数末尾がアンダースコアの内部関数で、認証済み入口・名変待ち照合・同期トリガーの登録は含まない。
4. 既存の車両差分同期で gf_vehicles に反映し、台帳の更新が先であることを確認する。以前の同期ソースには GF_SB_統合同期、5分の設定関数、差分の一括上限がある。現在の実行間隔と同じレコードを更新する他のジョブを確認し、書き込み担当を確定する。保存後の表示は台帳の保存完了と複製の照合完了を区別する。
5. LINEマイページのコードはLINEトークン検証、承認済みのDriverID、契約完了を使って進捗を返す。現行コードの読む gf_driver_vehicle_progress と、台帳から同期する gf_vehicles の接続を確定する。現行画面の接続先では、同じDriverIDの車両が複数ある。申込に紐付く車両を特定できない場合は、既存表示を継続して進捗を表示しない。車両を任意に1件選ばず、各段階の日付の保持方法も確認する。既存LINE設定とID紐付けを再利用する。
6. 複製台帳で、2台・2人、同一DriverIDの複数台、古い画面、保存連打・応答消失、同期停止・復旧、処理中の台帳直編集、取消との競合、権限なし、正しい本人以外に表示されないことを確認する。試験前後で入力規則、チェックボックス、トリガー、カレンダー転記を比較する。

ScriptLock が直列化するのは同一プロジェクト・同じロックを取得するGAS同士。Sheets APIで書き込み直前と直後を再読取しても、その間のシート直編集や別プロジェクトからの更新を排除できない。複製環境で競合時の検出と回復を確認し、運用上の競合窓を狭める。

## バックアップと、承認後の手順

1. 本番台帳を入力規則・書式を含めてGoogleスプレッドシート形式で複製。GASソースとマニフェスト、現行のデプロイ版と配信コミット、トリガー一覧、Supabaseの変更対象レコードをアクセス制限された場所に控える。切替直前の台帳とDBの照合結果を記録する。
2. 承認された変更だけを適用する。右端に納車2列を追加し、既存列とカレンダーを確認する。GASは既存認証・割当取消から内部関数を呼ぶ独立ファイルと最小の接続変更を追加する。高度なGoogle Sheets APIサービスは複製環境で有効にし、本番側の設定・スコープを事前確認する。
3. 現行同期の読取プレビューで差分と上限を確認し、承認された少数車両で「保存 → Sheets APIで再読取 → Supabase → 同じDriverIDのマイページ」を照合する。台帳直編集と進捗後の取消も確認してから対象を広げる。
4. 異常時は追加の書き込み入口と追加ジョブを止め、対象のGASデプロイを旧バージョンへ、画面/APIを旧リリースへ戻す。旧同期の担当と稼働を確認する。追加列の値は控えを取って残し、誤更新した行だけを切替記録と比較して回復する。切替後の正当な更新もあるため台帳全体を上書きしない。回復した台帳から差分同期し、DBとマイページを再照合してから再開する。

## テスト

車両進捗の既存4件、スタッフ7件、LINE版7件、新しいGAS候補5件とLINE版の関連確認1件が合格（計24件）。候補のSheets API・Supabase照合はモックで検証。別系統のマイページの index.html に対する既存テスト6件は未変更の基準コミットで失敗を確認した。現在の旧画面の段階や取得経路とテストの期待が異なるため、公開入口の確認後に対応範囲を確定する。
