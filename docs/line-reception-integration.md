# GOLD FIRST LINE受付管理｜本番接続仕様（作業用）

## 入口と認証
- 入口は将来的に gf-ledger/ 。共通ログイン実装担当が入口を統合する。
- 受付画面: line-reception-admin.html。既存トップ index.html と portal/index.html のログイン実装は本作業で変更しない。
- ブラウザの認証済みセッションだけではスプシ閲覧権限を認めない。API側でJWT検証とサーバー側の管理者/スタッフ権限確認を必須とする。
- 公開GitHub PagesにGAS認証情報、Googleサービスアカウント鍵、Supabase secret/service_roleを配置しない。

## 正本
- GOLD FIRST LINE受付管理 Google Sheets（IDは契約ライセンス管理からサーバー側で解決）。
- シート「LINE受付管理」: 受付ID, 受付日時, 受付種別, LINEユーザーID, DriverID, ドライバー名, VehicleID, 車番, 受付内容, ステータス, 担当者, 写真フォルダURL, 対応メモ, 完了日時, 契約者メールアドレス, 契約状況, 仮押さえ状態, 仮押さえ日時, 代車開始予定日, 代車返却予定日, 代車予定連携状態, 代車予定連携日時, 代車予定連携結果, 任意保険送信キー, 事故報告送信キー, 事故写真削除日時。
- シート「車両依頼受付」: 受付番号, 受付日時, 氏名, フリガナ, 電話番号, 紹介元, 所属会社名, 稼働エリア, 契約者メールアドレス, 緊急連絡先氏名, 緊急連絡先電話番号, 緊急連絡先メールアドレス, 納車希望, 稼働開始希望, 既存候補判定, 受付状態, 免許証PDF, 住民票PDF, 書類フォルダ, 書類状態, LINE受付ID, 受付識別子, 免許証確認, 住民票確認, 既存ドライバー確認, 確認DriverID, 契約内容確認, 契約状況, 契約更新日時。

## 一覧API
- 初期表示は「LINE受付管理」の受付種別が「車両依頼」のレコードのみ。
- 「車両依頼受付」はLINE受付IDと受付IDの一致を第一候補として照合する。受付番号/受付識別子との一致は現行GASの生成規則を確認するまで推測しない。
- 他カテゴリの受付処理や行は削除せず、画面に表示しないだけ。
- 一覧は受付ID、日時、氏名、受付内容、ステータス、担当者、対応メモ、関連する書類・契約状況を返す。
- 受付IDの不一致・重複はエラーとして扱い、氏名だけで自動結合しない。

## 保存API
- 編集可能: 既存GASで許容されているステータス（未対応/受付済/対応中/確認待ち/完了）、担当者、対応メモ。
- 受付IDを必須とし、受付種別「車両依頼」の対象行のみ更新。IDやDriverID、VehicleID、氏名などを画面入力で上書きしない。
- 保存処理は既存GASの「スタッフLINE受付を保存する」に合わせる。受付一覧取得は「スタッフLINE受付データを取得する」を再利用する。
- 競合更新、二重送信、権限不足、対象行なしは明示エラー。サーバー側で監査ログを残す。
- 既存GASのLINE Webhook、車両依頼、代車仮押さえ、予定連携、他カテゴリ処理は変更しない。

## 実装前の接続条件
- 認証付きAPIのサーバー側権限判定方式とGoogle Sheetsアクセス方式が必要。
- GitHub Pagesは静的ホストのため google.script.run を直接呼べない。
- GAS Webアプリを公開匿名APIに変更しない。公開GAS URLを埋め込んだだけの接続は不可。
- 代車契約発行は既存契約の正式文面を確認するまでプレビューのみ。正式な送信はマネーフォワード。
- 本番の読み書き接続・保存テスト完了前に「接続済み」「保存可能」と表示しない。
